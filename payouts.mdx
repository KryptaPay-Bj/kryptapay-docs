title: "Send payouts"

A **payout** sends money from your wallet to a recipient. The amount plus fee is reserved from your wallet as soon as the payout is created, and released if it fails or is cancelled.

## 1. Check the fee (optional)

[Quote a fee](/api-reference/fees/quote) tells you the fee and the total debit before you commit, and `maxSendable` tells you the largest payout your balance allows.

```bash
curl "https://staging.api.krypta-pay.com/v1/fees/quote?direction=PAYOUT&amount=15000&currency=XOF&network=MTN_BJ" \
  -H "Authorization: Bearer $KRYPTAPAY_API_KEY"
```

## 2. Create the payout

Always send an `Idempotency-Key` — a UUID you generate and store with your record first. If the request times out, retry with the **same** key: you'll get the original payout back instead of paying twice.

```bash
curl https://staging.api.krypta-pay.com/v1/payouts \
  -H "Authorization: Bearer $KRYPTAPAY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 4b17ddc6-4d7f-4d3e-a7d5-62e3c7f2d18d" \
  -d '{
    "amount": "15000",
    "currency": "XOF",
    "network": "MTN_BJ",
    "recipient": { "msisdn": "22997000000", "fullName": "Koffi Mensah" },
    "description": "Supplier payment #1042",
    "category": "suppliers"
  }'
```

```json
{
  "ok": true,
  "data": {
    "id": "cmgx2k1qv0001s60f8h3n5z7a",
    "reference": "tx_V1StGXR8Z5jdHi6BmyT",
    "status": "PROCESSING",
    "amount": "15000",
    "currency": "XOF",
    "fee": "150",
    "network": "MTN_BJ",
    "recipient": { "msisdn": "22997000000" },
    "idempotencyKey": "4b17ddc6-4d7f-4d3e-a7d5-62e3c7f2d18d",
    "autoExecuted": true,
    "frozen": false
  }
}
```

A `201` means the payout was **accepted**, not that the recipient has the money yet.

### Recipient fields by network

| Network | Required in `recipient` | Example |
| --- | --- | --- |
| Mobile Money (e.g. `MTN_BJ`) | `msisdn` | `97000000`, `22997000000` or `+22997000000` |
| `BANK_NGN` | `accountNumber` + `bankCode` | NUBAN `0123456789`, bank code `044` |
| Crypto (`ETH`, `POLYGON`, `TRON`) | `address` | Wallet address on that chain |
| Other bank rails (`BANK_XOF`, `BANK_XAF`, `BANK_GHS`, `BANK_CDF`, `BANK_EUR`, `BANK_USD`) | At least one identifier, e.g. `iban` | Settled manually by KryptaPay today |

<Warning>
  `recipient.bankName` and `recipient.bankId` are informational only. Use `recipient.bankCode` to identify the bank.
</Warning>

## 3. Track the result

You receive `PAYOUT_COMPLETED` or `PAYOUT_FAILED` by [webhook](/webhooks):

```json
{
  "event_id": "evt_2Lp8RtYu6Io0PaSdFgHjKl9Z",
  "event_type": "PAYOUT_COMPLETED",
  "created_at": "2026-10-27T10:15:42.000Z",
  "data": {
    "transaction_id": "cmgx2k1qv0001s60f8h3n5z7a",
    "reference": "tx_V1StGXR8Z5jdHi6BmyT",
    "amount": "15000",
    "currency": "XOF",
    "network": "MTN_BJ",
    "status": "COMPLETED"
  }
}
```

You can also fetch it any time with [Get a payout](/api-reference/payouts/get), using its `id` or `reference`.

## Reviews and holds

Most payouts are executed automatically (`autoExecuted: true`). Some stay `PENDING` for a while:

- **Manual approval** — depending on amount and account settings, some payouts are reviewed by KryptaPay before being sent.
- **Compliance hold** — `frozen: true` means the payout is under compliance review. Don't resubmit it; it continues or is cancelled once reviewed. Contact support if it lasts.

A payout that is still `PENDING` can be cancelled with [Cancel a payout](/api-reference/payouts/cancel), which releases the reserved funds. Once `PROCESSING`, it can no longer be cancelled (`409 bad_status`).

## Statuses

| Status | Meaning | Final |
| --- | --- | :-: |
| `PENDING` | Accepted; waiting for approval, review or execution. | |
| `PROCESSING` | Sent to the network; waiting for confirmation. | |
| `COMPLETED` | Delivered to the recipient. | ✅ |
| `FAILED` | Not delivered (invalid account, operator rejection…). Reserved funds are released. See `failureReason`. | ✅ |
| `CANCELLED` | Cancelled before execution. Reserved funds are released. | ✅ |
| `REFUNDED` | Reversed after completion. | ✅ |

## Common errors

| Code | Fix |
| --- | --- |
| `insufficient_funds` / `insufficient_funds_with_fee` | Top up, or lower the amount to `maxSendable`. |
| `limit_exceeded` | Lower the amount or ask support to raise your limits. |
| `network_unavailable` | Retry later or use another network. |
| `duplicate_within_window` | A same payout was sent less than 60 s ago — check `details.existingReference`. |

The full list is in [Errors](/errors).
